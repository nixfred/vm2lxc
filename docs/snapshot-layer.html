Snapshot-mount layer

vm2lxc, slice 2, first increment. Written 2026-11-17 by Larry:gus. Status: design + code against fakes, never run on a real host

1. What it is for

Give the guest-internal checks (and later the copy step) a read-only view of each VM disk's filesystems without ever modifying the source volume, and guarantee that everything it creates is removed again, even on a crash. Decision D1 (storage-level snapshots, not qm snapshot), BRIEF section 6.3.

2. Flow

inspect <vmid>                                   (plan is always printed first)
  read: qm config, pvesm path <storage:volume>   -> source dataset / LV for every data disk
  plan: pure function, no host calls
  --yes? no  -> stop here, nothing executed
        yes  -> take run lock, create journal, install trap (EXIT, INT, TERM)
                 1. snapshot   all source zvols in ONE atomic command
                 2. clone      each snapshot, readonly=on, stamped
                 3. dev-ready  settle udev, wait for the device and its partitions
                 4. mount      each supported filesystem read-only under /run/vm2lxc/<run>/
                 5. pick the guest root, run the guest checks against it
        always -> teardown in reverse: umount, destroy clones, destroy snapshot, rmdir, close journal

clone / device<parent>/vm2lxc-<vmid>-<run>-<diskkey>, readonly=on, stamped; device /dev/zvol/<clone>, partitions -partNmade read-only with lvchange -pr, activated -ay -K, partitions via kpartx -a -r
mounts/run/vm2lxc/<run>/<diskkey>/<partition>

The source dataset or LV is only ever the origin of a snapshot. It is never opened, written, renamed or property-edited (snapdev=visible would edit it, so it is not used).

5. Journal (write-ahead)

One file per run: /var/lib/vm2lxc/runs/<run>/journal (persistent across reboots, because the clones are). Tab-separated, append-only, human-readable:

# vm2lxc journal v1
RUN   <run>   <vmid>   <epoch>
STEP  <seq>   <kind>   <arg> ...
ST    <seq>   PENDING | DONE | UNDONE | FAILED
CLOSED

A step is journalled PENDING before it runs. A crash therefore leaves a step that may exist, and teardown checks real state before undoing it (so undo is idempotent, and safe to run twice). The latest ST line wins. CLOSED is written only after teardown verified everything is gone.

One flock on /var/lib/vm2lxc/lock serialises inspect --yes and cleanup. cleanup that finds the lock held says so and touches nothing.

6. Safety rails

These matter most, because this is the first code in the project that can destroy anything.

#RailEnforced by
R1Only names matching our patterns are ever destroyed or unmounted (@vm2lxc-<run>, /vm2lxc-<vmid>-<run>-<key>, paths under the run root).host_cmd argument validation
R2Only objects recorded in the journal of a run we own are touched. Nothing is found by scanning or by pattern alone.teardown reads the journal, not the pool
R3Before destroying, re-verify identity: the vm2lxc:run stamp equals the run id, and a clone's origin equals the recorded snapshot. A mismatch refuses, exit 77, and leaves the object alone.undo handlers
R4Never a recursive or forced flag: no -r, -R, -f, no umount -l. A snapshot with dependents therefore fails safe instead of taking children with it.host_cmd allowlist
R5A target equal to a source dataset/LV is refused outright.planner and host_cmd
R6Every mutating command passes one function, host_cmd, an allowlist of exact argument shapes. Anything else dies. It lives only in lib/hostexec.sh.allowlist + static test
R7Mounts are read-only only (ro must be in the options), only for filesystems in the table above, and only on devices under our own clone path.host_cmd mount
R8inspect executes nothing without --yes, and refuses to execute at all in fixture mode and when not root on a PVE node.command code + tests
R9A pre-existing object with the name we are about to create is a refusal, never adopted.apply handlers

8. Assumptions that only a real host can confirm

  • pvesm path <storage:vol> prints /dev/zvol/<pool/ds> for zfspool and /dev/<vg>/<lv> for lvmthin.
  • zfs snapshot -o vm2lxc:run=... and zfs clone -o readonly=on -o vm2lxc:run=... are accepted for zvols on PVE 8/9's OpenZFS.
  • zvol partition nodes appear as <clone>-part1 after udevadm settle.
  • lsblk -nrpo NAME,FSTYPE <dev> lists the device and its partitions with filesystem types.
  • A read-only clone of a snapshot of a running VM's zvol mounts cleanly with ro,noload (crash-consistent).
  • The BRIEF's checksum proof (source volume bit-identical before and after) still has to be run on a disposable nested PVE.
